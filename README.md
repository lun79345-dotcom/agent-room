# Agent Room · Mac 内测版 0.2

[English](README.en.md) · [官网介绍](https://nickstudio.cn/agent-room.html?lang=zh) · [下载 Mac 内测版](https://github.com/lun79345-dotcom/agent-room/releases/tag/v0.2.0)

![Agent Room 协作流程示意](docs/agent-room-overview.svg)

这是独立开发的本地协作工具，与 OpenAI 和 Anthropic 没有官方隶属关系。

一个本地员工协作群：用户、Claude 主管、两位 Codex 员工在同一条消息流里讨论、分工和汇报。一个员工绑定一个固定会话，之后持续沿用；可打开现有 Claude Desktop 或 Codex 应用继续工作。

双击 **启动员工群.command** 会启动独立后台服务；关闭启动窗口或调试连接后群聊仍继续运行。也可在本目录执行 `npm start` 以前台方式运行。启动后会给出本机地址，默认 <http://127.0.0.1:4319>，端口被占用时会自动选择其他本机端口。没有第三方运行时依赖，需要 Node.js 22+，以及已经登录的 Claude Code 和 Codex CLI。优先发现当前机器的已安装版本；“使用前检查”会检测程序、CLI 登录、所需接口和工作目录；可在窗口中手动填写程序位置，配置只保存在本机 `.data/settings.json`。环境变量 `AGENT_ROOM_CLAUDE` / `AGENT_ROOM_CODEX` 仍可指定可执行文件并优先于本机配置，`AGENT_ROOM_PORT` 可改端口。

首次安装先打开 [开始使用.html](开始使用.html)。解压后保留整个文件夹；移动文件夹前先停止服务，移动后检查员工工作目录。

## 使用

1. 群聊讨论：选择员工或所有员工，发送消息。使用真实模型，保留每个人自己的上下文。
2. 交办工作：选 Claude 主管并提交具体工作。主管返回分工，系统把工作交给指定 Codex 会话；员工完成后由主管汇总一次。后台执行和在原应用执行使用同一个会话。
3. 员工卡片的“去 Claude / Codex 工作”打开原应用中的绑定会话。Codex 员工在原应用中仍可从群聊联系：群消息进入同一会话的消息队列，由持有会话的应用接收，回复自动回到群聊。队列通常约 10 秒被原应用发现，正在进行的工作会先完成。Claude 员工在原应用工作时暂停群聊轮次，结束后点“回群聊”恢复联系。原应用其他已完成回复约每 12 秒同步，也可点“同步进度”。
4. 失败的讨论消息可按提示手动再联系。失败或中断的任务可在详情中“继续这项任务”，员工先核对已完成成果再继续。重启不会自动重做工作；使用“重新启动群聊.command”或“停止员工群.command”管理本文件夹自己的后台服务，有进行中的群聊工作时会拒绝直接关闭。
5. 员工设置可更改名字、职责、工作目录，或绑定已有会话 ID。一个会话只能绑定一位员工。移出小组保留原会话与历史消息。

默认工作目录是本目录的 `workspace/`。实际项目请在员工设置中指定已有文件夹。两位员工可以负责同一项目的不同文件；当前版本没有自动创建独立 Git worktree，主管应减少同一文件的同时修改。

## 已实现与边界

- Codex 使用官方 app-server 的 JSON-RPC 流式接口，持久化真实线程；使用 `codex://threads/<id>` 打开现有桌面应用。原应用持有会话时，改用 `thread/queue/add` 投递，以客户端消息 ID 对应原会话回复，不争抢写入权，也不新建员工会话。消息队列属于实验接口，本机已验证 Codex CLI 0.162.0-alpha.2。原应用释放会话后，可恢复同一会话接收尚未开始的队列消息。
- Claude 使用已安装 CLI 的持久会话；以 `claude --desktop --resume <id>` 打开 Claude Desktop 的 Code 会话，需要 Claude Code 2.1.285+ 和可用订阅。
- Claude 主管通过结构化分工安排员工。每一批工作完成后只自动汇报一次，不无限互相触发。所有自动工作都要由用户选择“交办工作”触发。
- 由群聊服务执行的讨论使用只读 Codex 沙箱；交办工作限制在员工工作目录，网络默认关闭。投递到原应用的轮次沿用原应用当前权限和确认流程，消息中要求讨论轮只汇报、不执行工作。Claude 群聊轮不启用执行工具或用户插件。
- 本版自动执行分工由 **Codex 员工**承担；额外加入的 Claude 员工可以讨论、绑定会话、进入原应用工作，执行结果可同步回来。
- “原应用 · 可联系”表示 Codex 会话由原应用保持，群聊可投递消息。它不代表工具能实时获知所有桌面活动。同步的是已完成的代理文本回复，不包含私有推理或全部工具日志。某些新版会话存储格式可能需要适配；失败会显示在员工卡片。
- Claude 提示会话已在别处打开时，不另起会话，显示“请切到该会话继续”。回群聊前请结束原应用正在进行的轮次；随后若再进入原应用，已经打开的旧视图可能需要重新打开会话以更新记录。本版没有对桌面内部的会话锁和视图刷新做自动控制。
- 队列尚未开始的消息可以从群聊撤回；已在原应用开始的轮次请在原会话停止，群聊会继续同步结果。若原应用上一轮被停止，队列可能需要在原会话继续后才会处理；页面会显示等待接收。
- 原应用入口仍需要用户点击；工具不会模拟鼠标持续接管桌面。Claude 主管在群聊中管理员工，进入原应用时可以继续原会话，但本版没有为原应用安装额外群聊 MCP 插件，原应用内不能主动调用群聊分工接口。

使用现有登录，不要求另填 API Key。实际模型调用会使用对应账户额度。Claude 的全局 AgentBridge 插件不会在本工具的群聊调用中加载；原应用按原来的设置运行。

## 数据与开发

群聊、员工绑定与任务保存在 `.data/room.json`（文件权限 600），不保存账户凭证。Claude / Codex 会话仍保存在各自的原生存储。服务仅监听 `127.0.0.1`，变更接口检查来源和页面令牌。不会扫描或同步无关会话。

源码入口是 `server.mjs`；`lib/adapters.mjs` 对接应用，`lib/store.mjs` 保存状态与分工约束；前端在 `public/`。

`npm test` 验证员工分工约束、重启时会话保留、中断处理、跨员工事件隔离、队列消息匹配、撤回边界和原应用回复筛选。正在进行的外部会话可能被独立读取接口显示为中断，工具读取原会话的实际结束记录确认，避免误判。验收演示文件会保存在 `workspace/trial/`，演示消息明确标注，不作为实际项目结果。

消息队列依据：[Codex 队列实现](https://github.com/openai/codex/blob/main/codex-rs/ext/queue/src/service.rs)、[官方队列接口测试](https://github.com/openai/codex/blob/main/codex-rs/app-server/tests/suite/v2/thread_queue.rs)。

接口依据：[Codex app-server](https://learn.chatgpt.com/docs/app-server)、[Codex 桌面会话链接](https://learn.chatgpt.com/docs/app/commands)、[Claude CLI --desktop](https://code.claude.com/docs/en/cli-reference)。

## 分享内测包

运行 `npm run package:mac` 生成 `release/agent-room-mac-beta-0.2.0.zip` 和校验文件。打包使用明确文件清单，排除所有本机 `.data`、历史会话、程序配置、项目文件及开发者截图。接收者首次启动会创建自己的员工。包内附 `开始使用.html`、`内测说明.md` 和文件校验清单，保留启动文件执行权限。

本包不捆绑 Node.js、Claude 或 Codex，也不是签名安装程序。当前定位为 Mac 本地内测，跨设备稳定性仍需收集实际反馈。

收费或托管服务应按厂商支持的登录方案接入，不能将当前复用本机 CLI 登录作为商业授权。参见 [OpenAI app-server 登录说明](https://learn.chatgpt.com/docs/app-server#auth-endpoints)。
